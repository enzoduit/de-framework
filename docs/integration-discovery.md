# Integration Discovery — Before You Configure pre_fetch.py

**Run this before writing any pre_fetch.py or kpis.yaml.**

The goal: find out exactly what data the client's DEs can actually reach, so you configure only what works — and document what's missing.

---

## Why This Matters

A KPI with no working data source is useless. A pre_fetch.py that crashes because an API token doesn't exist burns tokens and produces noise. Discovery first, configure second.

---

## Step 1 — Run the Discovery Script

```bash
bash /root/.openclaw/workspace/de-framework/scripts/discover-integrations.sh
```

This script probes common integration types and prints a status table:

```
[Integration Discovery Report]
==============================
Salesforce           ✓ READ   — GET /services/data/v58.0/sobjects → 200
Meta Ads             ✓ READ   — GET /act_<id>/insights → 200
Google Ads           ✗ FAIL   — No GOOGLE_ADS_DEVELOPER_TOKEN found
DataCrush            ✗ FAIL   — Connection refused (host: datacrush.io:443)
Yoizen               ⚠ PARTIAL — Auth OK but /contacts endpoint → 403
Power BI             ✗ MISSING — No credentials provided
Telegram             ✓ READ   — Bot token valid, chat reachable

Summary: 2 ready, 1 partial, 4 missing
```

Status meanings:
- `✓ READ` — credentials exist, test call succeeded
- `✓ WRITE` — credentials exist, write permission confirmed
- `⚠ PARTIAL` — auth works but access is restricted
- `✗ FAIL` — credentials exist but call failed (wrong token, blocked IP, etc.)
- `✗ MISSING` — no credentials found at all

## Step 2 — Document What You Found

Create `/var/de-agents/<client-name>/integrations.yaml`:

```yaml
# integrations.yaml — generated by integration discovery
# Update this file if credentials change

client: "<client_name>"
discovered_at: "<ISO timestamp>"

integrations:
  salesforce:
    status: ready          # ready | partial | missing | fail
    access: read           # read | read-write
    base_url: "https://<instance>.salesforce.com"
    env_var: SALESFORCE_TOKEN
    test_endpoint: "/services/data/v58.0/sobjects"
    notes: "Standard users only — no admin scope"

  meta_ads:
    status: ready
    access: read
    account_id: "act_123456"
    env_var: META_ACCESS_TOKEN
    test_endpoint: "/v19.0/act_123456/insights"

  google_ads:
    status: missing
    env_var: GOOGLE_ADS_DEVELOPER_TOKEN
    notes: "Client needs to generate API token from Google Ads console"
    setup_url: "https://developers.google.com/google-ads/api/docs/first-call/dev-token"

  datacrush:
    status: fail
    notes: "Connection refused — check if IP whitelisting is needed"
    action_needed: "Ask client to whitelist server IP: <server_ip>"

  yoizen:
    status: partial
    access: read
    notes: "/contacts → 403. Ask client to grant contacts read scope"

  telegram:
    status: ready
    access: read-write
    chat_id: "-1001234567890"
    env_var: TELEGRAM_BOT_TOKEN
    notes: "Human supervisor channel for Level-2 decisions"
```

## Step 3 — Map Integrations to DEs

For each DE, only enable KPIs that have `status: ready` or `status: partial` data sources.

```yaml
# Example: Paid Marketing Mass DE

kpis:
  - id: cpl_meta
    name: "Cost per Lead — Meta"
    measure: "python3 workspace/measure_cpl_meta.py"
    unit: "USD"
    direction: lower_is_better
    target: null
    target_auto: true
    target_improvement: 0.10
    requires_integration: meta_ads      # ← mark which integration feeds this

  - id: cpl_google
    name: "Cost per Lead — Google"
    measure: "python3 workspace/measure_cpl_google.py"
    unit: "USD"
    direction: lower_is_better
    target: null
    target_auto: true
    target_improvement: 0.10
    requires_integration: google_ads    # ← missing → this KPI will be skipped
    status: pending_integration         # ← pre_fetch skips this; logs it as blocked
```

`pre_fetch.py` reads `requires_integration` and checks `integrations.yaml`. If `status != ready`, it logs:
```
[KPI SKIPPED] cpl_google — google_ads integration not ready (status: missing)
```
instead of crashing.

## Step 4 — Generate the Missing-Integrations Checklist

After discovery, produce a short client-facing checklist of what they need to provide:

```markdown
## Missing Integrations — Action Required

To fully activate your digital team, the following credentials are needed:

| Integration | What's Needed | Where to Get It |
|-------------|--------------|-----------------|
| Google Ads | Developer Token + OAuth credentials | [Google Ads API Console](https://developers.google.com/google-ads/api) |
| DataCrush | IP whitelist for server `<server_ip>` | DataCrush admin panel → API Access |
| Yoizen | Extend API scope to include `/contacts` | Yoizen support ticket |
| Power BI | Service principal + report embed token | Azure AD → App registrations |

DEs that depend on these integrations will start in **benchmark mode** with available data, and automatically pick up the missing metrics once credentials arrive.
```

Send this checklist to the client before the first DE deployment. DEs don't need to wait — they start with whatever is available.

## Step 5 — Store Credentials Securely

Credentials belong in `/etc/de-framework.env` (or client-specific `/etc/<client>-framework.env`), not in any workspace file:

```bash
# Add new credentials to the env file:
echo "SALESFORCE_TOKEN=<token>" >> /etc/de-framework.env
echo "META_ACCESS_TOKEN=<token>" >> /etc/de-framework.env
echo "TELEGRAM_BOT_TOKEN=<token>" >> /etc/de-framework.env
```

Then verify the service picks them up:
```bash
systemctl restart de-backend
curl -s http://localhost:8769/health
```

Each measure_*.py script reads from environment variables — never hardcoded values.

## Common Integration Patterns

### Salesforce (most Fundraising clients)

```python
# measure_churn.py — minimal Salesforce query
import os, requests

TOKEN = os.environ["SALESFORCE_TOKEN"]
INSTANCE = os.environ["SALESFORCE_INSTANCE_URL"]

r = requests.get(
    f"{INSTANCE}/services/data/v58.0/query",
    params={"q": "SELECT COUNT(Id) FROM Opportunity WHERE StageName='Churned' AND CloseDate = LAST_MONTH"},
    headers={"Authorization": f"Bearer {TOKEN}"}
)
print(r.json()["totalSize"])  # pre_fetch expects a single number
```

### Meta Ads

```python
# measure_cpl_meta.py
import os, requests

TOKEN = os.environ["META_ACCESS_TOKEN"]
ACCOUNT = os.environ["META_ADS_ACCOUNT_ID"]

r = requests.get(
    f"https://graph.facebook.com/v19.0/{ACCOUNT}/insights",
    params={"fields": "cost_per_unique_click", "date_preset": "last_7d", "access_token": TOKEN}
)
data = r.json().get("data", [])
print(data[0]["cost_per_unique_click"] if data else "0")
```

### No API available (manual reporting)

If a client has no API but sends weekly CSV reports, the measure script reads the latest file instead:

```python
# measure_donations.py — reads latest CSV export
import glob, csv, os

files = sorted(glob.glob("/var/de-agents/<client>/imports/donations_*.csv"))
if not files:
    print("not_measured")
    exit(0)

with open(files[-1]) as f:
    rows = list(csv.DictReader(f))
print(len(rows))  # count of donations in latest export
```

This is a valid fallback. The DE still runs, KPIs still update — just on a delay matching the reporting cadence.
